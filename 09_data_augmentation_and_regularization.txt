Suppose we train a CNN on these images:

The model may become very good at recognizing the exact training images.

For example:

Training accuracy = 98%
Validation accuracy = 72%

That is a warning sign.

The model has learned the training data extremely well, but it doesn't generalize equally well to unseen images.

This is called: Overfitting

2. What Is Overfitting?

Overfitting happens when a model learns the training data too specifically.

Think of a student preparing for an examination.

Student A

Memorizes:

Question 1 → Answer A
Question 2 → Answer B
Question 3 → Answer C

Then the teacher changes the questions slightly.

Student A struggles.

Student B

Understands the underlying concepts.

Even when the questions change, Student B can solve them.

A good ML model should behave like Student B.

3. Underfitting vs Good Fit vs Overfitting

We can visualize the three situations like this:

UNDERFITTING
Training accuracy:   65%
Validation accuracy: 63%

The model hasn't learned enough.
GOOD FIT
Training accuracy:   90%
Validation accuracy: 87%

The model generalizes well.
OVERFITTING
Training accuracy:   99%
Validation accuracy: 72%

The model memorized too much.

The goal isn't necessarily:

"Get 100% training accuracy."

The goal is:

Build a model that performs well on unseen data.

5. Why Data Augmentation Works

Imagine a model sees:

       🐱

Then another image:

       🐱

but the cat is slightly shifted.

A robust model should still say:

CAT

Augmentation teaches the model:

"Don't rely on the exact position, orientation, or appearance of the training image."

This can improve generalization.

6. Important Rule: Augment Training Data, Not Validation/Test Data

This is extremely important.

Training data

Use augmentation:

Training
   ↓
Random transformations
   ↓
CNN
Validation/Test data

Usually:

Validation/Test
       ↓
Resize / Tensor / Normalize
       ↓
CNN

Why?

Because validation and test data should represent the data distribution we actually want to evaluate.

We don't want random transformations changing the evaluation every time.

13. Normalization

Normalization standardizes the image channels.

For ImageNet-style preprocessing:

transforms.Normalize(
    mean=[0.485, 0.456, 0.406],
    std=[0.229, 0.224, 0.225]
)

For CIFAR-10, commonly used dataset-specific statistics are approximately:

mean = [0.4914, 0.4822, 0.4465]
std = [0.2470, 0.2435, 0.2616]

So:

transforms.Normalize(
    mean=[0.4914, 0.4822, 0.4465],
    std=[0.2470, 0.2435, 0.2616]
)

Normalization helps put input values into a more suitable numerical range.

18. Dropout

We already encountered Dropout in Lesson 7.

Example:

nn.Dropout(p=0.3)

During training, approximately 30% of the selected activations are randomly set to zero.

Conceptually:

Before Dropout:

[0.2, 0.8, 0.4, 0.9, 0.1]

          ↓

After Dropout:

[0.2, 0, 0.4, 0, 0.1]

The exact behavior is handled internally by PyTorch.

19. Why Dropout Helps

Without dropout, the network may become overly dependent on particular neurons.

Dropout forces the network to learn more distributed representations.

Think of it as:

"Don't depend on one specific teammate. Learn the concept well enough that different teammates can contribute."

20. Dropout Example
self.dropout = nn.Dropout(p=0.3)

Then:

x = self.dropout(x)

Typical values include:

0.2
0.3
0.5

But the correct value depends on the architecture and dataset.

21. Important: Dropout During Training vs Evaluation

When we call:

model.train()

Dropout is active.

When we call:

model.eval()

Dropout is disabled.

Therefore:

model.train()

for training.

And:

model.eval()

for validation/testing.

This is one reason why forgetting model.eval() can produce incorrect evaluation behavior.

22. Weight Decay

Weight decay is another regularization technique.

It discourages excessively large model weights.

Suppose the model learns weights like:

10.8
-14.2
23.7
-19.5

Large weights can sometimes contribute to overfitting.

Weight decay encourages the model to keep weights more controlled.

23. Weight Decay with Adam

Example:

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001,
    weight_decay=1e-4
)

Here:

lr = 0.001

is the learning rate.

And:

weight_decay = 0.0001

is the regularization strength.

24. What Does 1e-4 Mean?

This:

1e-4

means:

1 × 10⁻⁴

which is:

0.0001

Other examples:

1e-3 = 0.001
1e-4 = 0.0001
1e-5 = 0.00001

25. Early Stopping

Suppose we train for 50 epochs.

We get:

Epoch   Train Loss   Val Loss
1       1.20         1.18
2       1.00         1.02
3       0.85         0.90
...
15      0.35         0.58
16      0.30         0.60
17      0.27         0.63
18      0.24         0.67

Notice:

Training loss ↓
Validation loss ↑

The model is beginning to overfit.

Instead of continuing to 50 epochs, we can stop.

This is: Early Stopping

26. Patience

We normally don't stop immediately after one bad epoch.

We define:

patience = 5

Meaning:

"If validation performance doesn't improve for 5 consecutive epochs, stop training."

27. Saving the Best Model

During training, we can save the model whenever validation loss improves.

if val_loss < best_val_loss:
    best_val_loss = val_loss

    torch.save(
        model.state_dict(),
        "best_model.pth"
    )

This is extremely useful.

Why?

Because the final epoch isn't necessarily the best model.

31. Data Augmentation vs Regularization

These concepts are related but not identical.

| Technique         | Main Purpose                         |
| ----------------- | ------------------------------------ |
| Data Augmentation | Increase variation in training data  |
| Dropout           | Prevent neuron co-adaptation         |
| Weight Decay      | Penalize large weights               |
| Early Stopping    | Stop before excessive overfitting    |
| LR Scheduler      | Adjust learning rate during training |

A strong Deep Learning pipeline may use several of them together.

59. Important Concept: Augmentation Depends on the Dataset

For CIFAR-10:

RandomHorizontalFlip
RandomCrop

are generally reasonable.

But imagine a dataset containing:

Road signs

A horizontal flip may change the meaning of certain signs.

Or a dataset containing:

Medical images

Some transformations may not be clinically appropriate.

Therefore:

Never apply augmentation blindly.

You don't necessarily need:

64. Data Augmentation vs More Data

Data augmentation doesn't literally give you permanently stored new images.

Instead, transformations can generate different versions during training.

For example:

Epoch 1:
Original → Crop A

Epoch 2:
Original → Crop B

Epoch 3:
Original → Crop C

So the model may encounter different variations over time.

What You Should Understand Before Lesson 10

By the end of Lesson 9, you should be able to explain:

1. What is overfitting?

When a model learns the training data too specifically and performs worse on unseen data.

2. What is data augmentation?

Creating realistic variations of training data to improve generalization.

3. Why use RandomHorizontalFlip?

To expose the model to horizontally flipped examples when that transformation preserves the label.

4. Why use RandomCrop?

To make the model less dependent on the exact spatial position of an object.

5. What is Dropout?

A regularization technique that randomly disables activations during training.

6. What is Weight Decay?

A regularization mechanism that discourages excessively large weights.

7. What is Early Stopping?

Stopping training when validation performance stops improving for a chosen patience period.

8. Why use a learning-rate scheduler?

To adjust the learning rate as training progresses, especially when improvement plateaus.

9. Should validation images normally receive random augmentation?

No. Validation/test preprocessing should generally be deterministic.

10. What is the main goal?

Generalization — performing well on data the model has never seen before.
